# GameDB

Service ตาราง Query สำหรับทีมงาน INBLACKM — เลือก query ที่บันทึกไว้เพื่อดึงข้อมูลจากฐานข้อมูล แสดงผลเป็นตารางที่จัดคอลัมน์เองได้ (เรียงลำดับ, ซ่อน, เปลี่ยนชื่อ, ระบายสี, เพิ่มคอลัมน์สูตร)

- Next.js 16 + Tailwind 4 — dev พอร์ต **4183**, production พอร์ต **5589** (PM2 app: `system.db.inblackm`)
- ตารางของ service นี้: `gamedb_users`, `gamedb_queries`, `gamedb_connections` (สร้างไว้แต่เดิม) + `gamedb_views`, `gamedb_user_layouts`, `gamedb_connection_flags`, `gamedb_snapshots`, `gamedb_edit_log` (service สร้างเอง จึงเป็นเจ้าของเองและไม่ต้องขอ GRANT)

## หน้าทำงาน

เปิดได้หลาย Query พร้อมกัน แต่ละอันเป็น panel ของตัวเอง

- **ปรับขนาด** — ลากขอบหรือมุมของ panel ได้ทุกด้าน, ลากขอบหัวคอลัมน์เพื่อปรับความกว้าง, ดับเบิลคลิกที่ขอบเพื่อรีเซ็ต
- **จัดวาง** — ลากจุดจับ (⣿) ไปวางทับอีก panel เพื่อสลับตำแหน่ง, ปุ่มขยายเต็มความกว้าง, ย่อเหลือหัวข้อ
- ตำแหน่ง/ขนาด/ตารางที่เปิดอยู่ จำไว้ใน localStorage แยกตามเครื่อง ส่วนการตั้งค่าของ Query เก็บใน DB (ปุ่ม "บันทึก Layout")
- **พารามิเตอร์** — เขียน `:ชื่อ` ใน SQL (เช่น `WHERE created_at >= :from`) ระบบจะสร้างช่องกรอกให้เอง ค่าถูกส่งเป็น bound parameter ไม่ได้ต่อสตริงเข้า SQL — ตั้งป้ายกำกับ/ชนิด (ข้อความ, ตัวเลข, วันที่, dropdown)/ค่าเริ่มต้นได้ที่ปุ่มพารามิเตอร์
- **รันซ้ำอัตโนมัติ** — เลือกรอบ 15 วิ – 15 นาทีต่อ panel, หยุดเองเมื่อสลับไปแท็บอื่น, เซลล์ที่ค่าเปลี่ยนจากรอบก่อนจะไฮไลต์เหลือง
- **เรียงลำดับ / สรุป** — คลิกหัวคอลัมน์เพื่อ asc → desc → ปิด, ปุ่ม Σ ในหัวคอลัมน์เพิ่มแถวสรุป (รวม/เฉลี่ย/ต่ำสุด/สูงสุด/นับ)
- **คอลัมน์สูตร** — คำนวณจากคอลัมน์อื่นในแถวเดียวกัน ผลลัพธ์เป็นตัวเลข ข้อความ วันที่ หรือใช่/ไม่ใช่ (เดาให้จากสูตร เลือกทับเองได้) หน้าต่างสูตรบอกทันทีว่าสูตรผิดตรงไหนและ**แถวแรกจะได้ค่าอะไร** · คอลัมน์สูตรที่สร้างแล้วแก้ชื่อ/สูตร/ชนิดผลลัพธ์ได้ทันทีจากเครื่องมือ hover บนหัวคอลัมน์
  - เขียนได้: `+ - * / ( )` · ต่อข้อความด้วย `&` · เทียบด้วย `= <> < <= > >=` · ข้อความใส่ใน `"..."` · อ้างคอลัมน์ด้วย `[ชื่อคอลัมน์]`
  - **เงื่อนไข** `IF(เงื่อนไข, ค่าเมื่อจริง, ค่าเมื่อเท็จ)` `AND` `OR` `NOT` `ISBLANK` `COALESCE` `IFERROR`
  - **วันที่** `TODAY()` `DAYSUNTIL(วันที่)` เหลืออีกกี่วัน (ติดลบ = เลยกำหนด) · `DAYS(ปลายทาง, ต้นทาง)` `ADDDAYS` `YEAR` `MONTH` `DAY` — อ่าน `dd/mm/yyyy` และปี พ.ศ. ได้
  - **ข้อความ** `CONCAT` `LEFT` `RIGHT` `MID` `LEN` `UPPER` `LOWER` `TRIM` `TEXT` `CONTAINS` · **ตัวเลข** `ROUND` `ABS` `MIN` `MAX` `SUM`
  - ค่าที่หายไปจะได้ผลว่าง (`—`) ไม่ใช่ `#N/A` หรือ `#VALUE!` — ใช้ `COALESCE`/`IFERROR` ใส่ค่าสำรองแทนได้
  - ตัวอย่าง: `IF(DAYSUNTIL([วันหมดอายุ SMS]) < 3, "OTP ใกล้หมดอายุ", "ปกติ")` · `CONCAT([PASS], " · ", LEFT([Mail], 12))`
- **ระบายสีตามเงื่อนไข** — กฎแบบ `คงเหลือ น้อยกว่า 10 = แดง` หรือแถบวัดระดับในเซลล์ตัวเลข · 16 สี (อ่อน 12 + ทึบ 4) · เลือกได้ว่าระบายเฉพาะช่องนั้นหรือ**ทั้งแถว** · เงื่อนไขข้อความ (มีคำว่า/ไม่มี/ขึ้นต้น/ลงท้าย/อยู่ในรายการ/ว่าง/ไม่ว่าง) และ**เงื่อนไขวันที่เทียบกับวันนี้** (เลยกำหนดแล้ว, ครบกำหนดภายใน N วัน, เป็นวันนี้ — อ่าน `dd/mm/yyyy` และปี พ.ศ. ได้) · ค่าที่เทียบใส่เป็น `[ชื่อคอลัมน์]` เพื่อเทียบกับอีกคอลัมน์ในแถวเดียวกันได้ เช่น `ยอดเข้า น้อยกว่า [ยอดออก]` · เปิดจากเครื่องมือ hover แล้วระบบเลือกคอลัมน์นั้นให้ทันที
- **รูปแบบคอลัมน์** — สีพื้น/สีตัวอักษร/สีหัวคอลัมน์แบบถาวรไม่ขึ้นกับค่า, ตัดบรรทัดข้อความยาว, จัดชิดซ้าย-กลาง-ขวา และเลือกได้ว่าคอลัมน์นั้นแสดงเป็นข้อความ, **ลิงก์** (โชว์แค่ชื่อโดเมน กดเปิดแท็บใหม่ — เฉพาะ `http(s)://` เท่านั้น), **อีเมล**, **ป้ายสี** หรือ**มีปุ่มคัดลอก** · กฎสีตามเงื่อนไขจะทับสีพื้นตรงนี้เมื่อเงื่อนไขเป็นจริง · เปิดจากเครื่องมือ hover แล้วการ์ดของคอลัมน์นั้นจะแสดงก่อน
- **ตรึงคอลัมน์ซ้าย** — ปักคอลัมน์แรกไว้ได้ถึง 5 คอลัมน์ ตารางกว้าง ๆ เลื่อนขวาแล้วยังรู้ว่าแถวไหน (ตั้งในหน้าต่างเดียวกับรูปแบบคอลัมน์)
- **หัวคอลัมน์ 2 ชั้น** — ใส่ "หัวกลุ่ม" ให้คอลัมน์ (พร้อมสีของมันเอง) คอลัมน์ที่**ติดกัน**และใส่ชื่อ+สีเหมือนกันจะรวมเป็นหัวเดียวคร่อมกัน เช่น "ยอด" คร่อม ยอดเข้า/ยอดออก/คงเหลือ · กลุ่มที่โดนคอลัมน์อื่นคั่นจะแยกเป็น 2 หัวชื่อเดียวกัน ไม่ใช่คร่อมทับคอลัมน์ที่ไม่ได้อยู่ในกลุ่ม · แถวหัวกลุ่มติดอยู่บนสุดเวลาเลื่อน และตรึงตามไปกับคอลัมน์ที่ตรึงไว้ถ้ากลุ่มนั้นอยู่ในเขตตรึงทั้งกลุ่ม
- **กราฟ + CSV** — สลับ panel เป็นกราฟแท่ง/เส้นจากผลลัพธ์เดียวกัน และดาวน์โหลด CSV (UTF-8 BOM เปิดใน Excel ได้)
- **จัดกลุ่ม / โฟลเดอร์ / ค้นหา** — ปุ่ม ▦ ในหัวคอลัมน์จัดกลุ่มแถวตามค่าในคอลัมน์นั้น (ยุบ-กางได้ พร้อมจำนวนแถว) · Query จัดเข้าโฟลเดอร์ได้ (ตั้งในหน้าแก้ไข Query) และปักหมุดตัวที่ใช้บ่อยไว้บนสุด · ช่องค้นหาด้านซ้ายค้นทั้งชื่อ คำอธิบาย และตัว SQL
- **Drill-down** — ตั้งว่าคลิกแถวแล้วเปิด Query ไหนพร้อมส่งค่าจากแถวนั้นไปเป็นพารามิเตอร์ (เช่นคลิกแพ็ก → เปิดออเดอร์ของแพ็กนั้น) panel ใหม่จะเปิดขึ้นมาพร้อมค่าที่กรอกให้แล้ว
- **snapshot** — ปุ่ม 📷 บันทึกผลลัพธ์ตอนนั้นเก็บไว้ (server รัน SQL ใหม่เองเพื่อให้ค่าเชื่อถือได้) แล้วเลือกดูย้อนหลังได้จาก dropdown พร้อมแถบเตือนว่ากำลังดูข้อมูลเก่า · ปุ่ม 🗑 ข้าง dropdown ลบตัวที่กำลังดูอยู่ ถ้าไม่ได้เปิด snapshot ไหนอยู่จะลบของ Query นั้นทั้งหมด (ถามยืนยันก่อน, เฉพาะ Admin)
- **แก้หลายแถวจาก Excel** — คัดลอกช่วงจาก Excel/Sheets มาวาง ระบบ preview ว่าจะแก้กี่เซลล์ แล้วเขียนกลับทีละแถว รายงานแถวที่ไม่สำเร็จแยกให้
- **Excel หลายชีต พร้อมสี** — ปุ่มบนหัวเว็บดาวน์โหลดทุกตารางที่เปิดอยู่เป็นไฟล์ `.xlsx` ชีตละตาราง (เขียน XLSX เองไม่เพิ่ม dependency) · ไฟล์ที่ได้**หน้าตาเหมือนบนจอ** — สีหัวคอลัมน์ สีเซลล์จากกฎเงื่อนไข/สีประจำคอลัมน์/สีทั้งแถว และหัวกลุ่มกลายเป็นเซลล์ merge คร่อมคอลัมน์ · ตารางที่ไม่ได้ใส่สีไว้ก็ยังได้ไฟล์ขนาดเท่าเดิม
- **โหลดเพิ่ม** — ผลลัพธ์ที่เกินลิมิตไม่ถูกตัดทิ้งเงียบ ๆ แต่มีปุ่มโหลดหน้าต่อไป และตารางเกิน 150 แถวจะ render เฉพาะแถวที่มองเห็น (ปิดเองเมื่อเปิด "ตัดบรรทัด" ในคอลัมน์ไหนก็ตาม เพราะความสูงแถวไม่เท่ากันแล้ว)
- **โหมดมืด + คีย์ลัด** — ปุ่ม 🌙 หรือกด `d` · `/` ไปช่องค้นหา · `r` รันทุกตารางใหม่ · `e` ดาวน์โหลด Excel
- **ความสูงโหมดชีต** — ครั้งแรกสูงพอดีกับพื้นที่หน้าจอที่เหลือ · ลากแถบเหนือแท็บด้านล่างขึ้น/ลงเพื่อกำหนดเองและจำค่าไว้ในเครื่อง · ดับเบิลคลิกแถบหรือกด `Home` เพื่อกลับเป็นขนาดอัตโนมัติ
- **รายการ Query เป็น dropdown** — ช่องค้นหาบนหัวเว็บกางรายการลงมา เลือกแล้วยุบเอง ไม่กินพื้นที่ถาวรจากตาราง
- **เครื่องมือหัวคอลัมน์** — ชี้ที่หัวคอลัมน์แล้วแถบเครื่องมือลอยขึ้นมาเหนือคอลัมน์นั้น (เลื่อนซ้าย/ขวา, Σ สรุป, จัดกลุ่ม, รูปแบบ, กฎสี, แก้สูตร, เปลี่ยนชื่อ, ซ่อน) · ใช้คีย์บอร์ดได้ — โฟกัสหัวคอลัมน์แล้วกด Tab เข้าไปในแถบ กด Esc กลับออกมา
- **รวมตารางข้าม Query** — จับคู่แถวกับอีก Query โดยเทียบคอลัมน์ตั้งแต่ 1 คู่ขึ้นไป (เช่น `sku = รหัส` และ `เกม = game` ต้องตรงทั้งคู่) แล้วดึงคอลัมน์ของอีกฝั่งมาแสดงต่อท้าย พร้อมคอลัมน์เช็ค `✓ ตรงกัน / ✗ ต่างกัน` เทียบค่าทีละคู่ · แถวที่ไม่มีคู่ขึ้น "ไม่พบคู่" และหัวตารางสรุปว่าจับคู่ได้กี่แถว · เทียบตัวเลขกับข้อความตัวเลขได้ (`10` = `"10"`) และข้อความไม่สนตัวพิมพ์/ช่องว่างหัวท้าย · การรวมทำในเบราว์เซอร์ ไม่ได้ JOIN ที่ฐานข้อมูล จึงข้าม DB คนละเครื่องกันได้

การตั้งค่าทั้งหมดของ Query (คอลัมน์, สูตร, พารามิเตอร์, กฎสี, รูปแบบคอลัมน์, คอลัมน์ที่ตรึงไว้, กราฟ, รอบรีเฟรช, การแก้ไขข้อมูล) เก็บรวมอยู่ในคอลัมน์ `layout` (JSONB) ของ `gamedb_queries` — ตั้งใจให้ไม่ต้อง `ALTER TABLE` เพิ่มคอลัมน์ เพราะ user ที่ service ใช้ไม่ได้เป็นเจ้าของตาราง

## สร้าง Query โดยไม่ต้องเขียน SQL (Admin เท่านั้น)

หน้าต่าง "เพิ่ม Query" มี 2 โหมด — **เลือกตารางและคอลัมน์** (ค่าเริ่มต้นตอนสร้างใหม่) กับ **เขียน SQL เอง**

- อ่านโครงสร้างจากฐานข้อมูลจริงผ่าน `pg_catalog` และแสดงเฉพาะตาราง/คอลัมน์ที่ **user ของ connection นั้นมีสิทธิ์อ่านจริง** (`has_table_privilege` / `has_column_privilege`)
- ค้นหาตารางจากชื่อตารางหรือชื่อคอลัมน์ · กรองเฉพาะที่ใช้ล่าสุด / มี Primary Key / มีคอลัมน์ที่แก้ไขได้ · 3 Template เริ่มต้น (ตารางทั่วไป, ข้อมูลล่าสุด, ตารางแก้ไขข้อมูล)
- **Join จาก Foreign Key** — ตารางที่เชื่อมกันด้วย FK ถูกเสนอให้อัตโนมัติ ติ๊กคอลัมน์ที่อยากดึงมา ระบบเขียน `LEFT JOIN` พร้อม alias ให้เอง (รองรับ FK หลายคอลัมน์)
- **ตัวกรอง** — เท่ากับ / ไม่เท่ากับ / มีคำว่า / ขึ้นต้น / ลงท้าย / มากกว่า-น้อยกว่า / อยู่ในรายการ / ว่าง / ไม่ว่าง · ช่องกรอกเปลี่ยนตามชนิดคอลัมน์ (ตัวเลข, วันที่, dropdown จริง/เท็จ) · เชื่อมกันด้วย `AND`
- **ติ๊ก "ให้แก้ไขค่าได้" รายคอลัมน์** — ระบบตั้งค่าการเขียนกลับให้เสร็จ และบังคับดึง Primary Key มาด้วยเพื่อให้ระบุแถวได้ · คอลัมน์ที่แก้ไม่ได้บอกเหตุผลกำกับ (DB อ่านอย่างเดียว / เป็น PK / ฐานข้อมูลสร้างค่าเอง / ไม่มีสิทธิ์ UPDATE)
- ตั้งชื่อหัวคอลัมน์ รูปแบบการแสดงผล สีเซลล์/สีหัว และสีทั้งตารางได้ตั้งแต่ในหน้าต่างนี้ ใช้งานได้ทันทีหลังกดบันทึก
- SQL ที่ระบบสร้างแสดงให้ดูเต็ม ๆ และรัน preview ให้อัตโนมัติระหว่างเลือก · ทุกชื่อตาราง/คอลัมน์ถูก validate + quote และค่าตัวกรองถูก escape เป็น literal ก่อนประกอบ SQL แล้วยังผ่านด่าน read-only เดิมอีกชั้นตอนบันทึก
- สลับไปดู "เขียน SQL เอง" แล้วกลับมาได้โดยไม่เสียสิ่งที่เลือกไว้ · เปลี่ยน "ฐานข้อมูล" ถึงจะโหลดโครงสร้างใหม่และเริ่มเลือกใหม่
- **ทำสำเนา Query** (เมนู ⋯ ของ panel) — คัดลอกทั้ง SQL และ layout ไปเป็น Query ใหม่ชื่อ "(สำเนา)"
- แก้ Query เก่าแล้วสลับมาสร้างใหม่ด้วยโหมดเลือกตาราง: การตั้งค่าที่ผูกกับตำแหน่งคอลัมน์เดิม (ซ่อน/ลำดับ/กฎสี/การเรียง) จะถูกล้าง เพราะคอลัมน์ชุดใหม่ไม่ใช่ชุดเดิมแล้ว — เหลือไว้แค่โฟลเดอร์กับรอบรีเฟรช

## Layout ส่วนตัว vs ส่วนกลาง

ปุ่มบันทึกในแต่ละ panel มี 2 แบบ

- **บันทึกของฉัน** — ใครก็กดได้ เก็บใน `gamedb_user_layouts` เห็นคนเดียว (มีป้าย "ของฉัน" ขึ้นเตือน กดเพื่อกลับไปใช้ค่ากลาง)
- **บันทึกให้ทุกคน** — Admin เท่านั้น เขียนลง `layout` ของ Query เป็นค่าเริ่มต้นที่ทุกคนเห็น

ลำดับความสำคัญเวลาแสดง: layout ส่วนตัว → เทมเพลตหน้าจอ → ค่ากลางของ Query

## เครื่องมือ Admin

- **ตรวจสุขภาพระบบ** (ไอคอน ⚕) — บอกว่า service ต่อ DB ด้วย user อะไร ใครเป็นเจ้าของแต่ละตาราง/sequence สิทธิ์ครบไหม และถ้าขาดจะ**พิมพ์ SQL `GRANT` ที่ต้องรันให้เลย** พร้อมปุ่มคัดลอก (เกิดจากที่เคยเจอ error 42501 ทั้งตารางและ sequence) · เตือนด้วยถ้า `SESSION_SECRET` หรือ `GAMEDB_ENC_KEY` ยังไม่ได้ตั้ง
- **ประวัติการแก้ไข** (ไอคอน 🕘) — ใครแก้อะไร ค่าเดิม → ค่าใหม่ พร้อมปุ่ม **ย้อนกลับ** ทีละรายการ
- **จัดการฐานข้อมูล** — ต่อ connection มี checkbox **"อนุญาตให้แก้ไขข้อมูล"** (ปิดไว้เป็นค่าเริ่มต้นทุกตัว รวมทั้ง DB หลัก) + ตั้ง timeout และจำนวนแถวสูงสุดต่อหน้าแยกต่อ connection

## เทมเพลตหน้าจอ — จัดหน้าให้คนอื่นใช้

Admin จัดหน้าจอไว้ (เปิดตารางไหน วางยังไง ซ่อน/เรียงคอลัมน์อะไร) แล้วกดปุ่ม **"เทมเพลต"** เพื่อบันทึกทั้งหน้าเป็นชุดเดียว จากนั้นเลือกว่าจะให้ใครใช้

- เก็บทั้ง **panel ที่เปิด + ขนาด/ลำดับ** และ **layout ของแต่ละตาราง ณ ตอนนั้น** (คอลัมน์ที่ซ่อน, การเรียง, คอลัมน์สูตร, กฎสี, กราฟ, รอบรีเฟรช)
- แชร์ได้ 2 แบบ: **ทุกคนในระบบ** หรือ **เลือกรายคน**
- ติ๊ก **"หน้าเริ่มต้น"** = คนที่ได้รับ เปิดเว็บมาครั้งแรกจะเจอหน้านี้เลย ไม่ต้องกดอะไร
- ผู้ใช้สลับได้เองที่ dropdown บนหัวเว็บ ระหว่าง **"หน้าจอของฉัน"** กับเทมเพลตที่ได้รับ — ออกจากเทมเพลตเมื่อไหร่ ก็กลับไปหน้าจอเดิมของตัวเอง
- layout ในเทมเพลต **ไม่ทับ** layout ที่บันทึกไว้กับ Query ดังนั้นส่งหน้าคนละแบบให้คนละทีมจาก Query เดียวกันได้
- แก้ชื่อ/การแชร์ ไม่ไปยุ่งกับหน้าจอที่บันทึกไว้ ถ้าอยากเปลี่ยนหน้าจอต้องกด **"อัปเดตด้วยหน้าจอปัจจุบัน"**
- staff เปิดใช้ได้อย่างเดียว สร้าง/แก้/ลบ/แชร์ เป็นสิทธิ์ Admin

เก็บในตาราง `gamedb_views` ซึ่ง service สร้างเอง จึงเป็นเจ้าของเองและไม่ต้องขอ GRANT เหมือนตารางชุดแรก

## แก้ไขข้อมูลจากตาราง (Admin เท่านั้น)

ปุ่ม "ตั้งค่าการแก้ไขข้อมูล" ในแต่ละ panel กำหนดว่า Query นี้เขียนกลับไปที่ **ตารางไหน / key คอลัมน์อะไร / แก้คอลัมน์ไหนได้บ้าง** จากนั้นดับเบิลคลิกเซลล์เพื่อแก้

- คอลัมน์ key ต้องอยู่ใน `SELECT` ด้วย ไม่งั้นระบบไม่รู้ว่าจะอัปเดตแถวไหน (เลือกจาก dropdown ของคอลัมน์ที่มีจริงในผลลัพธ์ ไม่ต้องพิมพ์เอง)
- **ช่องแก้ไขตามชนิดของข้อมูล** — ดับเบิลคลิกเซลล์แล้วได้ช่องที่ตรงกับคอลัมน์นั้นเอง โดยไม่ต้องตั้งอะไร: `boolean` เป็น dropdown `true / false / ไม่ระบุ` · จำนวนเต็ม (`int2/4/8`) รับเฉพาะเลขจำนวนเต็ม ส่วน `numeric`/`float` ใส่ทศนิยมได้ · `date` กับ `timestamp` เป็นตัวเลือกวันที่ · ที่เหลือเป็นช่องข้อความ
- **ตั้งช่องกรอกเองรายคอลัมน์** — ที่ "ตั้งค่าการแก้ไขข้อมูล" เลือกได้ว่าคอลัมน์ไหนเป็นช่องแบบไหน **ใช้ทั้งตอนดับเบิลคลิกแก้ในตารางและตอนเพิ่มแถว**
  - **เลือกจากรายการที่พิมพ์เอง** — พิมพ์ตัวเลือกคั่นด้วย `,` · เขียน `ป้าย = ค่าที่เก็บ` ได้เมื่อสิ่งที่โชว์กับสิ่งที่เก็บต่างกัน เช่น `Bot Auto = BOT_AUTO, Manual = MANUAL` (จำเป็นกับคอลัมน์ที่มาจาก `CASE`) · ค่าที่มีอยู่แล้วแต่ไม่อยู่ในรายการจะถูกใส่กลับให้เลือกพร้อมป้าย "(ไม่มีในรายการ)" ไม่ใช่หายไปเงียบ ๆ
  - **เลือกจากอีกตาราง (FK)** — บอกชื่อตาราง + คอลัมน์ที่โชว์ + คอลัมน์ที่เก็บ เช่น `topup.payment_channel` / `name` / `id` แล้ว dropdown จะดึงรายการจากตารางนั้นมาให้ **โชว์ชื่อแต่เขียน id ลง FK** · อ่านครั้งเดียวต่อ panel, `ORDER BY` คอลัมน์ที่โชว์, จำกัด 500 แถว · ชื่อตาราง/คอลัมน์มาจาก config ที่บันทึกไว้เท่านั้น ไม่รับจาก request และ Admin เท่านั้นที่เรียกได้
- **Query ที่ตั้งชื่อคอลัมน์ด้วย `AS`** — ชื่อในผลลัพธ์กับชื่อคอลัมน์จริงในตารางเป็นคนละอันได้ เช่น `e.id AS "ID"` หรือ `coalesce(e.note,'') AS "หมายเหตุ"` จึงมีช่อง **"ชื่อจริงในตาราง"** ให้กรอกทั้งของ key และของแต่ละคอลัมน์ที่อนุญาตให้แก้ · เว้นว่าง = ใช้ชื่อเดียวกัน (Query ที่ไม่ได้ตั้ง alias ไม่ต้องกรอกอะไรเลย เหมือนเดิมทุกประการ)
  - ชื่อในผลลัพธ์เป็นแค่ป้าย จะมี `/` ช่องว่าง หรือภาษาไทยก็ได้ ไม่เคยถูกส่งเข้า SQL — ที่ถูก quote ลง SQL คือชื่อจริงเท่านั้น และต้องผ่าน validate เหมือนเดิม
  - **คอลัมน์ที่มาจากการคำนวณหรือ JOIN เขียนกลับไม่ได้** (`CASE ... END AS "..."`, `g.name`, `rpad(repeat(...))`) — เอาออกจากรายการ "คอลัมน์ที่อนุญาตให้แก้" เพราะไม่มีคอลัมน์จริงให้เขียน
- เขียนทีละ 1 เซลล์ ใน transaction ที่ `SELECT ... FOR UPDATE` ก่อน และยกเลิกถ้าแตะโดนมากกว่า 1 แถว
- ชื่อตาราง/คอลัมน์มาจาก config ที่บันทึกไว้เท่านั้น (ไม่รับจาก request) และถูก validate + quote ก่อนประกอบ SQL — รองรับชื่อภาษาไทย
- ทุกครั้งที่แก้สำเร็จจะบันทึกลง `gamedb_edit_log` (ใคร, ตาราง, แถว, คอลัมน์, ค่าเดิม → ค่าใหม่, เวลา)
- ค่าว่าง = `NULL` · staff แก้ไม่ได้ (403)

### เพิ่ม / ลบทั้งแถว

ติ๊กเปิดแยกจากการแก้เซลล์ ในหน้าต่างเดียวกัน — ปิดอยู่โดยปริยาย และ Query ที่ตั้งค่าไว้ก่อนหน้านี้ยังปิดอยู่

- **เพิ่มแถว** — เมนู "เพิ่มเติม → เพิ่มแถวใหม่" เปิดฟอร์มที่สร้างจากคอลัมน์ที่อนุญาตให้แก้ · ตั้งช่องกรอกรายคอลัมน์ได้ (ข้อความ / ตัวเลข / วันที่ / เวลา / วันที่+เวลา / เลือกจากรายการ / หลายบรรทัด / ใช่-ไม่ใช่) พร้อมค่าเริ่มต้น (`@today` `@now` `@time` แทนค่าให้ตอนเปิดฟอร์ม) และ "ต้องกรอก"
- **ช่องที่เว้นว่างจะไม่ถูกใส่ในคำสั่ง `INSERT` เลย** คอลัมน์นั้นจึงได้ `DEFAULT` ของตารางเอง (สำคัญกับ serial และ `created_at`) — ไม่ใช่ส่ง `NULL` ไปทับ
- เขียนได้เฉพาะคอลัมน์ที่อยู่ในรายการ "อนุญาตให้แก้" เท่านั้น การเปิดเพิ่มแถวจึงไม่ทำให้เขียนคอลัมน์ที่แก้ไม่ได้
- **ลบแถว** — ปุ่ม 🗑 ตรงเลขแถว (โผล่ตอนเอาเมาส์ชี้) ถามยืนยันพร้อมค่า key ก่อนเสมอ · อ่านแถวไว้ก่อนด้วย `FOR UPDATE` แล้วยกเลิกถ้าไม่เจอ (404) หรือเจอมากกว่า 1 แถว (409)
- ทั้งสองอย่างบันทึกลง `gamedb_edit_log` เหมือนการแก้เซลล์ — เพิ่มแถวเก็บค่าที่เขียน ลบแถวเก็บค่าทั้งแถวที่หายไป (ตัดที่ 2000 ตัวอักษร)
- ผ่านด่านเดียวกับการแก้เซลล์ทุกด่าน: Admin เท่านั้น + ฐานข้อมูลต้องติ๊ก "อนุญาตให้แก้ไขข้อมูล" + ค่าทุกตัวส่งเป็น bound parameter
- **มีระบบ login ของตัวเอง** — ตาราง `gamedb_users` + cookie `gamedb_session` แยกขาดจาก inblackm, รหัสผ่านแฮชด้วย scrypt, กัน brute force 8 ครั้ง/10 นาที
- **ต่อหลายฐานข้อมูลได้** — Admin เพิ่ม connection PostgreSQL อื่นผ่านปุ่ม "ฐานข้อมูล" แล้วเลือกได้ต่อ query (รหัสผ่านถูกเข้ารหัส AES-256-GCM ด้วย `GAMEDB_ENC_KEY` ก่อนเก็บ)

## เริ่มใช้งาน (dev)

```bash
npm install
cp .env.example .env   # แล้วเติมค่าตามด้านล่าง
npm run dev            # http://localhost:4183
```

ค่าใน `.env`:

| ตัวแปร | ค่า |
|---|---|
| `PG_HOST` / `PG_PORT` / `PG_DATABASE` / `PG_USER` / `PG_PASSWORD` | PostgreSQL ที่เก็บตาราง `gamedb_*` |
| `SESSION_SECRET` | คีย์เซ็น session cookie ของ gamedb เอง (string ยาว ๆ อะไรก็ได้) — **บน production ไม่ตั้งแล้วแอปจะไม่ยอมทำงาน** เพราะถ้า fallback ไปใช้คีย์ในโค้ด ใครก็ปลอม cookie เป็น admin ได้ |
| `TURNSTILE_ENABLED` | ตั้ง `true` เพื่อบังคับ Cloudflare Turnstile ที่หน้า login; เมื่อเปิดแล้วแต่ key ไม่ครบ ระบบจะปฏิเสธ login แบบ fail-closed |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` / `TURNSTILE_SECRET_KEY` | Site Key ที่ส่งให้ widget และ Secret Key ที่ใช้ตรวจ token ฝั่ง server ตามลำดับ ห้ามนำ Secret Key ไปใช้ใน client หรือ commit ลง Git |
| `TURNSTILE_ALLOWED_HOSTNAMES` | hostname ที่ยอมรับจากผล `siteverify` คั่นด้วย comma เช่น `systemdb.inblackm.com,localhost` เพื่อกัน token จาก hostname อื่น |
| `GAMEDB_ENC_KEY` | คีย์เข้ารหัสรหัสผ่าน connection (ตั้งแล้วห้ามเปลี่ยน ไม่งั้น connection เดิมถอดรหัสไม่ได้) |
| `GAMEDB_ADMIN_USERNAME` / `GAMEDB_ADMIN_PASSWORD` | บัญชี admin คนแรก — ถูกสร้างอัตโนมัติครั้งเดียวตอนตาราง `gamedb_users` ยังว่าง |

## ผู้ใช้และสิทธิ์

- login ที่หน้าแรกด้วย username/รหัสผ่านจากตาราง `gamedb_users` (ไม่เกี่ยวกับบัญชี inblackm)
- role `admin`: จัดการ Query, จัดการฐานข้อมูล, ทดสอบรัน SQL ได้ทั้งหมด
- role `staff`: ดู, รัน query, จัด layout ได้
- เพิ่มคนหรือเปลี่ยนรหัสผ่าน: ตอนนี้ทำผ่าน SQL ตรง ๆ เช่น ล้างแล้ว seed ใหม่ — `DELETE FROM gamedb_users;` แล้วแก้ `GAMEDB_ADMIN_*` ใน `.env` + restart (จะ seed ใหม่ตอนตารางว่าง)
- SQL ทุกคำสั่งถูกบังคับ: `SELECT`/`WITH` statement เดียว + คัดกรองคีย์เวิร์ด (อ่านเฉพาะนอก string literal/comment) + รันใน transaction `READ ONLY` + timeout 8 วินาที + จำกัด 1,000 แถว
- ค่าที่ผู้ใช้กรอก (`:param`) ถูก bind เป็น `$n` เสมอ ไม่ต่อสตริงเข้า SQL · ชื่อตาราง/คอลัมน์ที่ประกอบเข้า SQL ตอนเขียนข้อมูลมาจาก config ที่ Admin บันทึกไว้ และถูก validate + quote
- ทุก API มี guard: ไม่มี cookie = 401 ทุกเส้น, staff แตะเส้นของ Admin = 403 · role อ่านจากฐานข้อมูลทุก request ไม่ใช่จาก cookie ดังนั้นถอดสิทธิ์แล้วมีผลทันที
- response header: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin` และ CSP (`frame-ancestors 'none'`; อนุญาต `challenges.cloudflare.com` เฉพาะ script/frame/connect ที่ Turnstile ต้องใช้)

## Deploy production

1. วาง `.env` บนเซิร์ฟเวอร์ (รวม `GAMEDB_ADMIN_USERNAME`/`GAMEDB_ADMIN_PASSWORD` สำหรับ seed รอบแรก)
2. `npm run build` แล้ว `npm run pm2:start` (PM2 app ชื่อ `system.db.inblackm`, พอร์ต 5589) — หรือปล่อยให้ GitHub Actions (`.github/workflows/deploy.yml`) ทำให้เมื่อ push `main`
3. เพิ่ม site ใน aaPanel/nginx: subdomain ชั้นเดียว เช่น `systemdb.inblackm.com` → reverse proxy `http://127.0.0.1:5589` (subdomain ซ้อน 2 ชั้นจะติดปัญหา cert ของ Cloudflare)
4. ใน Cloudflare Turnstile เพิ่ม hostname `systemdb.inblackm.com` ให้ widget แล้วกำหนด `TURNSTILE_ENABLED=true` พร้อม Site Key/Secret Key ใน `.env` ก่อน restart PM2

GRANT USAGE, SELECT ON SEQUENCE gamedb_queries_id_seq TO system_database;
